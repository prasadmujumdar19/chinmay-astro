Design Principles (v2.0): This map is drawn from scratch — independent of current workflow IDs.
Key upgrades vs MVP: (1) Intent Filter on all free-form messages, borrowed from FDF WF-35/WF-36.
(2) Consent gate before any DB write (FDF J1 pattern). (3) User keywords HELP / STOP / REBOOK for self-service.
(4) Two-dimensional state tracking: status + stage. (5) Graceful handling of all non-text message types.

J-18 HELP keyword — any state FDF
TRG User sends text "HELP" (case-insensitive) from any state

  • Respond contextually based on current status:
    • new/consented: explain next step (fill form)
    • payment_pending: resend payment instructions
    • payment_submitted: confirm payment under review
    • consultation_active: confirm relay is live, Chinmay can see messages

J-19 STOP keyword — user-initiated unsubscribe (Meta regulatory requirement) FDF
TRG User sends "STOP" from any state. Intercepted at WF-20 before any other routing. MVP Day 1 — required for Meta go-live.
  • Intercept at WF-20 before any other routing (exact keyword match, case-insensitive)
  • All states (unconditional): update status = opted_out and clear current_consultation_id. STOP is honoured immediately — no hold, no queueing — to align with standard WhatsApp / regulatory STOP semantics. opted_out is NOT blocked — distinct from admin BLOCK.
  • If userStatus was consultation_active at the time of STOP: also auto-close the open consultations row (status='closed', ended_at=NOW(), closed_by='user_opted_out') so it isn't left dangling.
  • If user has a Slack consult channel (users.slack_channel_id IS NOT NULL — i.e., user progressed past form submission): post an opt-out notice via WF-51 to that channel so the astrologer knows the conversation won't progress further. Channel is preserved per DR-10 (not archived) in case of future REBOOK.
  • Send confirmation to user: "You have been unsubscribed from Chinmay Astro. No further messages will be sent unless you reach out to us again."
  • Future messages from opted_out users: WF-01 routes to new journey — treat as brand new user (re-trigger J-01 welcome + form flow). DB record is NOT deleted.
  • Handled by WF-47 (Unsubscribe Handler) — called from WF-20. No write to admin_actions (table deprecated per TD-NEW-026 — opt-out fact is recoverable from users.status + users.updated_at + inbound STOP messages row).
any → opted_out
⚠️ opted_out ≠ blocked. opted_out = user chose to leave (regulatory). blocked = admin/system action for bad behaviour. Handled differently in WF-01 routing and admin tooling.

TRG User who previously sent STOP (status=opted_out) sends any message

Intent Filter Design FDF Pattern

Intent Filter (WF-25) is a shared sub-workflow called by any workflow that needs to classify ambiguous free-form user messages. Modelled on FDF WF-05. Uses Gemini 2.5 Flash Lite (temperature=0, max 20 tokens) for fast, cheap classification. Returns structured intent + passthrough of original input fields.

Applied in (MVP): WF-23 (pre-form), WF-30 (payment_pending), WF-31 (payment_submitted), WF-43 (consultation_closed)

Intent classes for Chinmay Astro: wants_consultation general_enquiry rebook_intent feedback_intent garbage malicious_abusive inappropriate

Key design rules:
• Keywords (HELP, STOP, REBOOK) are intercepted at WF-20 before the Intent Filter — exact keyword match, no LLM.
• garbage: warn user, notify admin via Slack (do not auto-block).
• malicious_abusive / inappropriate: warn user, notify admin in Slack + trigger BLOCK flow via WF-46 (auto-block on abuse).
• stop_intent (user expresses desire to leave in free-form, not exact STOP keyword): acknowledge + guide toward sending STOP keyword. Do not auto-unsubscribe from free-form.
• All callers pass: phoneNumber, userId, messageText, userStatus, userStage.
• WF-25 returns: original fields + intentResult (one of the classes above).
