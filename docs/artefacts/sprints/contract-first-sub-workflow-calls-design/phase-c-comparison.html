Type contradictions

  • logged: pseudo=boolean runtime=boolean (exec ids: 1878, 1877)
Subagent notes: Runtime executions 1878 and 1877 both followed the skip-log path (no userId resolved), so the successful INSERT path with logId is not confirmed by runtime sample — logId type is inferred from static code ($input.item.json.id from RETURNING id clause). Critical bug observed: the Done node hardcodes `logged: true` and is wired to ALL terminal branches (success insert, filter skip, no-userId skip), so callers always receive `logged: true` regardless of whether the message was actually logged — the `logged: false` outputs from skip branches are silently overwritten. The type_contradictions entry is a placeholder acknowledging this bug; the type is correct (boolean) but the value contract is broken at runtime. All 4 callers use passthrough mode with no explicit workflowInputs_schema, so caller_missing_required and dead_pass findings would require confirmed defineBelow/Set-node evidence which is absent here.
