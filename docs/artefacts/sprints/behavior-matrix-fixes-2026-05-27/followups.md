### [2026-05-29] build-workflow Step 6a dangling-ref scan must also cover connection TARGET names, not just `$('…')` expression refs
- **Target:** `build-workflow` Step 6a (and `impact-analysis` Step 2a — same scan).
- **Observed on:** BMX-P2-WF02. Renamed node `Is Text Message?` → `Existing-User Text?`; the transform updated the node's own outgoing-connection KEY and all `$('…')` expression refs, but missed the **incoming connection target** (`Detect Route.main → "Is Text Message?"`), leaving a dangling connection target. - **Gap:** Step 6a as written scans only `$('NodeName')` expression references. n8n connections reference nodes by NAME in two places — the connection KEY (source) and each entry's `.node` (target). - **Fix:** extend the Step 6a scan to also walk `.connections[*].main[*][*].node` for any reference to a removed/renamed name (in addition to the `$('…')` grep). One jq pass: `jq '[.connections[].main[][].node] | map(select(. as $n | $REMOVED | index($n)))'`. Flag any hit as a BLOCKER identical to a dangling expression ref.
- **Priority hint:** medium (cheap deterministic check; prevents a silent broken-edge class on every rename/remove). Flush via `flush-plugin-improvements` at batch boundary.

## [2026-05-30] — Sub-agent-driven audit: execution learnings (BMX-P5-DRIFT)

This session ran a successful 11-agent parallel read-only audit (Sonnet, background, all ≤219s under a 300s cap). Concrete learnings to fold into `dispatching-subagents` / `build-sprint` Mode-D guidance at sprint-close flush. **Target:** `n8n-whatsapp-methodology:dispatching-subagents` (+ a possible new "audit fan-out" pattern in `build-sprint`).

- **Pure-read analysis agents eliminate the permission-wall failure mode.** Designing every agent as Read-only (no Bash/Write/Edit/MCP) — parent does ALL downloads, generation, and writes — meant zero mid-flight permission stalls across 11 agents. This is the operational realization of `[[feedback_subagent_permission_preauth]]`. **Recommend:** make "audit/analysis agents return structured text, parent owns all I/O" the *default* documented pattern for fan-out, not just an option.
- **Self-contained prompts with embedded reference + absolute paths prevent blockers.** Each agent got (a) the full data-contract convention reference inlined (written once to scratch by the parent), (b) exact absolute scratch paths for its `.md`/`.pseudo`, (c) an explicit "no decisions need user input — note ambiguity and continue." No agent had to search, guess, or ask. **Recommend:** a prompt checklist for Mode-D dispatch: inputs-by-absolute-path, embedded reference, explicit no-ask clause, strict output template.
- **Completion-notification collection beats active Monitor polling at this fan-out width.** `run_in_background:true` + the harness's per-agent completion notifications scaled cleanly to 11 agents; a single cheap `sleep 290` backstop timer covered the 300s cap (went unused — slowest 219s). Active 60s Monitor polling of 11 transcripts would have been noise. **Recommend:** for N≥~5 short read-only agents, prefer completion-notifications + one backstop timer over per-agent Monitor loops. (The 2-min CLAUDE.md abort budget assumed 1–3 agents; codify a wider-fan-out variant.)
- **Static-`.md` agents over-flag; a parent live-verification pass is mandatory.** One agent rated "empty `defineBelow value:{}` mapping = HIGH bug"; parent verification (checking WF-02's own working calls) proved it a FALSE POSITIVE. Conversely the WF-43 mis-key was real AND the parent found the same defect in WF-31 that the agent missed. **Recommend:** agents must TAG uncertain structural findings `[VERIFY-LIVE]`; build an explicit parent verification stage into any audit workflow before findings are reported as confirmed. Add to `build-sprint` cross-cutting audit discipline.
- **Right-size chunks to the cap; ~3 workflows/agent held all under 219s.** Mixed-size workflows: 2–3 per agent kept even a 65K-token agent under cap. **Recommend:** sizing heuristic for read-audit agents ≈ 3 medium artifacts per agent for a 300s budget.
- **Parent-deterministic + agent-reasoning split is the core efficiency win.** Parent ran the curl loop + `generate-workflow-md.py` (deterministic, would have hit sandbox/permission issues and duplicated effort inside agents); agents only did the LLM-judgment comparison. Never push deterministic I/O into agents. Reinforces `[[feedback_parallel_subagent_background_dispatch]]` + CLAUDE.md Subagent-Delegation rule 4.
- **Sonnet was the correct tier (user-mandated, justified).** Tracing field-flow (messageText vs messageContent across WF-02→handler→WF-25) needed Sonnet-level reasoning; Haiku would likely miss it. ~450K subagent-tokens total for 11 agents over 31 workflows. **Note for the Haiku-default rule:** audit/drift reasoning is a legitimate Sonnet-justified case — document it as an example where the "ask before Sonnet" gate is expected to clear.

Mitigated manually in this sprint by restating the contract inline in the WF-25 item + a hard dep on WF-30/31/43.
