🟠 Check 4 — Expression Format Errors (Missing = Prefix)

7 NODES AFFECTED ▾

Postgres query fields with {{ expression }} inside literal text require an = prefix

Without the prefix, the entire field is treated as a literal string — the expression is not evaluated. The SQL sent to Postgres contains {{ $json.phoneNumber }} as text, causing either zero rows matched or a query error.

Note: Project CLAUDE.md warns "= prefix breaks base64 encoding" — this applies specifically to WhatsApp Flows fields, not Postgres query fields. These are different node types.

🔴 Check 9 — Postgres Schema vs. Workflow SQL

2 CRITICAL MISMATCHES ▾

Missing column: users.stage F-01

The chinmay_astro.users table has no stage column. Two workflows reference it in UPDATE queries — both will throw column "stage" does not exist at runtime.

WorkflowNodeSQL
WF-44 Feedback Recorder Save Feedback to DB SET feedback = $1, stage = NULL, ...
WF-45 Rebook Handler Set status=payment_pending SET status = 'payment_pending', stage = NULL, ...
Option A (preferred): ALTER TABLE chinmay_astro.users ADD COLUMN stage VARCHAR(50); — aligns with the registry's "two-dimensional state" design (status + stage).
Option B: Strip stage = NULL from both UPDATE queries if stage tracking is not yet implemented.

Wrong column names in admin_actions INSERTs F-02

The admin_actions table has columns action_type and notes. Two workflows INSERT using wrong column names, causing SQL errors on every admin action log attempt.

WorkflowNodeWrongCorrect
WF-47 Unsubscribe Handler opt-out INSERT action action_type
WF-11 Command Parser UNBLOCK INSERT action, reason action_type, notes
Fix F-02: Update the INSERT SQL in both nodes to use action_type and notes. Alternatively, add alias columns to the table — but fixing the queries is cleaner.
