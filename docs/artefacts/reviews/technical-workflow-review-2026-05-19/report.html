ADJ-T4 — Plugin improvement: tighten C13 regex (false positive on safe ={{ $json.preBuiltJson }}) ⚪

Current regex ^=\s*[\{\[] matches both the safe whole-body-expression form ={{ expr }} and the broken raw-string-template form ={"f":"{{ x }}"}.

Tighten: require character after first { / [ to NOT be {. Pattern ^=\s*\{[^\{] for object-literal broken form; ^=\s*\[[^\{] for array-literal broken form. Optionally additionally require the body to contain }}, {{ OR end with a literal ".

Action: flush to plugin via flush-plugin-improvements skill (out of scope of this sprint).

ADJ-T5 — Plugin improvement: C12 alias-tolerance hint ⚪

C12 inspects only the upstream node type. WF-22 → WF-52 trips ⚠️ because upstream is a postgres node. But WF-52's Prepare Channel Name has explicit aliasing:

const phoneNumber = input.phone_number || input.phoneNumber || '';
const userName = input.name || input.userName || '';

Proposed extension: allow docs/well-known-downstreams.yml to declare accepts_aliases per required key, e.g.:

- workflowId: IO5BZLUxuVmjzk5I   # WF-52
  required_keys: [phoneNumber, userName]
  accepts_aliases:
    phoneNumber: [phone_number]
    userName: [name]

C12 can then check upstream postgres SELECT/INSERT RETURNING column names against the alias set and suppress the warning when satisfied.

Action: flush to plugin (out of scope).
